# Windows backend scaffold

Verified 7 October 2026: Windows 11 x64, PowerShell 7, Temurin JDK 25.0.4.1+1, Maven Wrapper 3.3.4, Maven 3.9.11 and Spring Boot 4.0.8. See the [dependency decision](../decisions/0001-backend-scaffold.md) for compatibility limits.

## Verified build and start/check/stop commands

Run from the repository root in PowerShell:

```powershell
$env:JAVA_HOME = Join-Path $env:LOCALAPPDATA 'Programs/Eclipse Adoptium/jdk-25.0.4.1+1'
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
.\mvnw.cmd --version
.\mvnw.cmd -B -ntp clean verify
.\scripts\Test-BackendHealth.ps1
```

Adjust `JAVA_HOME` if your JDK 25 installation is elsewhere. Maven's version output must show Java 25 and Eclipse Adoptium. These environment changes affect only the current shell. Host Maven is unnecessary when using the wrapper. The first build needs Maven Central network access and writable user Maven caches. Both wrapper scripts are generated by the official wrapper plugin; `.mvn/wrapper/maven-wrapper.properties` pins Maven 3.9.11. The Unix script is supplied but untested.

The smoke script starts the packaged JAR with the selected `java.exe`, `-jar` and `target/agenticawithakka-0.0.1-SNAPSHOT.jar` using `Start-Process -WindowStyle Hidden`. It waits up to 45 seconds, calls `http://127.0.0.1:8080/api/health` with `Invoke-WebRequest`, checks the response and stops only its own process in `finally`. Keep port 8080 free and use default application configuration for this check. It leaves no server running. Logs are in `target/health-smoke.stdout.log` and `target/health-smoke.stderr.log`. Startup failures, timeout and unexpected responses fail the script.

Observed output:

```text

Java version: 25.0.4.1, vendor: Eclipse Adoptium

BUILD SUCCESS
```

## Configuration and package boundaries

`application.yaml` binds HTTP to `127.0.0.1:8080`. The sole custom setting, `app.service-name`, defaults to `agenticawithakka`: nonblank, at most 64 characters, starting with a lowercase letter, then lowercase letters, digits or hyphens. Unknown `app.*` settings fail startup. This identifier is public and must contain no secrets. Spring's external configuration mechanisms remain available; future provider settings are not implemented or validated.

`GET /api/health` reports process status and the service identifier only, not database, model, agent, source or production readiness. It is public and local. Business endpoints do not exist; identity and project authorization must precede their implementation.

The single Maven application uses `io.agenticawithakka`. `config` owns configuration/composition; `api` owns HTTP. Since 8 October 2026, `domain/contracts` and `application/ports` contain versioned contracts and port interfaces ([decision 0003](../decisions/0003-domain-contracts-and-ports.md)), and `tools` contains the policy-gated read-only tool registry and the three Phase 1 read tools ([decision 0004](../decisions/0004-tool-registry-and-permissions.md)). Since 9 October 2026, `security` and `connectors/mock` contain local in-memory identity, policy and synthetic delegated-source adapters ([decision 0005](../decisions/0005-identity-policy-mock-connectors.md)); these do not implement OIDC/JWT authentication or production source access. Remaining reserved boundaries are `agents`, `skills`, `retrieval`, `persistence` and `observability`; they contain only package documentation, not implementations. Domain types must remain independent of Spring AI, Akka, HTTP and vendor credentials.

## Verification evidence

- Official wrapper generation succeeded using `maven-wrapper-plugin:3.3.4:wrapper`, `maven=3.9.11`, `type=only-script`.
- `clean verify` succeeded with `release 25` and produced the executable JAR. `ServicePropertiesTest` passed 7 cases for valid, missing, blank, malformed, oversized and unknown configuration. `HealthEndpointTest` passed 2 tests on a real random-port HTTP server, including absence of business and configuration-management endpoints.
- Packaged-JAR smoke check returned HTTP 200 and the exact two-field body above; the process was stopped.
- Repeated the build (9 passing tests) and packaged smoke check from a fresh source-only copy in a temporary Windows path containing spaces. No existing `target` output was copied. This reused the user Maven cache; it was not an empty-cache or committed-checkout test.
- Surefire reports are generated in `target/surefire-reports` and not committed.
- Maven/Guice emitted a deprecated `sun.misc.Unsafe` warning; Mockito/Byte Buddy emitted dynamic-agent warnings. Neither failed this JDK 25 run; future JDK compatibility is not inferred.
- Spring AI and Akka are absent from the dependency graph. Publication availability and vendor support statements are not proof of combined application compatibility; access, licensing and integration tests remain pending.

## Execution-environment blocker

Normal workspace execution was tried with PowerShell (also an explicit executable and login disabled) and `cmd.exe`. Even `pwd`/`cd` failed before launching a shell, with this exact tool error:

```text
CreateProcess { message: "Rejected(\"Failed to create unified exec process: helper_unknown_error: setup refresh had errors\")" }
```

Normal wrapper and smoke-script attempts returned the same error. The observed failure is execution-helper setup, not a Maven, Java or test failure. Its underlying cause could not be inspected through the failed shell. Explicitly approved outside-sandbox executions completed the verification above; normal sandboxed execution remains unverified and blocked. Administrator PowerShell is not an application prerequisite. Repair/reinitialize the agent execution environment rather than make elevated execution the default build procedure.
